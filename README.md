## Where to start

If you have just finished **Chapter 1**, start with:

1. **Asset 1** — paste the master prompt into your model and run it against one real brief.
2. **Asset 2** — build the four tables before you run anything else. Empty tables have no failure mode, and every downstream asset needs a row to point at.

Do not skip to Chapter 3's worksheets. The promise worksheet is unanswerable until you have a grounded brief, and the brief is unanswerable until the tables exist.

---

## A note on Asset 2

The Four-Table Storage Base is the only asset that is more than a single text file. The folder contains:

- `four-table-base.txt` — the full schema, column definitions, status rules, and setup instructions for Airtable, Notion, and Sheets
- `ideas.csv`, `briefs.csv`, `drafts.csv`, `products.csv` — import-ready headers with one example row each

**Start with the `.txt`.** The CSVs are for importing once you know what the columns mean. Delete the example rows before your first real batch.

## How these files are written

Each file has the same shape:

- **How to use this file** — what it is, what it replaces, what not to skip
- **`START COPYING HERE` … `STOP COPYING HERE`** — the part you actually copy
- **Reference material** — tests, rules, and worked shapes, below the copy block
- **Build Session** — the checklist from the end of the matching chapter

The copy block is the asset. Everything below it is the reasoning, kept in the same file so it travels with the thing it explains.

## What is deliberately missing

- **No royalty rates.** Asset 7 leaves the price bands blank on purpose. Open your own KDP account, write the current terms down by hand, and re-derive your price at every launch. Any number printed here would be wrong within a year and confident about it.
- **No fifth table.** Asset 2 stops at four tables. The Assets table appears the day your first asset ships, not before. An empty table is a schema you will redesign in week three.
- **No finished copy.** Assets 9 and 10 are scaffolds, not emails and not landing pages. Every claim in them has to trace to a grounded Ideas row. Where the evidence does not exist yet, the template says `[NEEDS INPUT: what is missing]` and means it.

---

## Two rules that apply to everything here

**No source, no brief.** An unsourced idea can sit in the Ideas table indefinitely, because raw costs nothing. A Briefs row cannot, because briefed is the state that triggers spend.

**One batch, one row type.** Never mix a drafting job and a research job in the same run. The prompt becomes a compromise between two tasks, and compromised prompts produce output you rewrite anyway.
